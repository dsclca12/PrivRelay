# 端到端加密

PrivRelay 的 Android 与 Web 客户端使用共享口令同步加密消息。E2EE 在服务端首次注册 E2EE 设备时全局启用；之后服务端拒绝旧明文消息 API 和新建非 E2EE 设备。

## 密钥与信封

- 每台客户端输入相同的端到端加密口令。口令不会发送到服务器；Android 将口令保存在 Android Keystore 保护的安全存储中，浏览器只在当前页面内存中保留不可导出的 AES 密钥，刷新页面后需重新输入。
- 服务端生成并在其加密存储中保存 16 字节随机 salt，通过已认证的 `/api/v2/crypto/params` 返回。客户端使用 PBKDF2-HMAC-SHA-256（600,000 次）派生 256 位密钥。
- 每条记录使用独立随机 96 位 nonce 和 AES-256-GCM，AAD 为 `PrivRelay-E2EE-v1`。线上 envelope 是 Base64URL 编码的 `version(1) || nonce || ciphertext || tag`。
- 完整消息对象在客户端加密后发往 `/api/v2/encrypted-messages/sync`。服务端不解析信封，只保存密文与消息 ID、设备 ID、接收时间、修订号等同步元数据。多设备需由用户在每台客户端输入相同口令。
- MMS 文本和已导入附件属于完整消息对象的一部分，因此同样由该信封加密。Android 每条 MMS 最多内嵌 2 MiB 附件；大于 2 MiB 的附件保留在系统 MMS Provider 并由详情页提示未同步。服务端单条密文上限为 3 MiB，批量 HTTP 请求上限为 5 MiB。

请使用长且随机的口令（建议至少 20 个字符）。服务端数据库副本包含公开 salt 和密文；弱口令可能受到离线猜测攻击。

## 功能边界

E2EE 启用后，服务端不能分类、全文搜索、审核纠错或导出短信正文。Android 使用本地索引，Web 客户端先下载并在浏览器中解密，再执行搜索和分页。服务端统计只反映密文条数，不包含正文类别。LLM 与远端分类器不会收到短信内容。

服务器仍能看到设备标识、消息 ID、接收时间、记录数量、密文长度和访问时间。TLS 仍保护网络链路和认证令牌；E2EE 与 TLS 相互补充，不能替代 HTTPS。

## 启用与旧数据

在 Android 配对设置或 Web 登录配对时输入同一加密口令（至少 12 个可见 ASCII 字符，确保各客户端派生密钥输入一致）。已配对的 E2EE 设备可以更新共享库中的密文记录。第一次注册 E2EE 设备后，旧明文 API 会立即停用，其他客户端需要升级并重新以 E2EE 模式配对。Android 会把本机缓存的记录重新加密上传，服务器只清理已确认上传对应密文的旧记录。仍有未迁移记录时，完成迁移接口返回 `409 migration_incomplete` 并保留原文；Web 配对不会自动清空旧短信。

遗留记录仍在服务端存储加密快照内，管理员持有存储密钥时可以读取；不能宣称全部历史已经端到端加密。当前 Web 无法读取未迁移的旧明文记录，需要原设备完成迁移。不要通过删除数据库、卸载客户端或强行清空未迁移记录来解决迁移提示。

密文更新使用 `base_revision` 做版本检查；另一台设备已更新时返回 `409 revision_conflict`，客户端读取最新密文后重放操作。服务端不会用旧版本静默覆盖新版本；客户端只有确认匹配的消息 ID、时间和密文 ACK 后才移除待发送操作。

管理员可选设置 `PRIVRELAY_RETENTION_DAYS`（默认 `0`，关闭）以限制服务端 E2EE 密文保存时间。期限从短信 `received_at` 起算；启用后会检查库内已有和新写入的密文。过期后服务删除密文并留下不含正文的 revision 墓碑，Android 和 Web 下次增量同步时删除本地记录及待处理操作。墓碑保留以通知长期离线设备；旧客户端应升级后再启用此策略。该期限不会清理旧明文迁移遗留、离线设备尚未同步的本地副本、备份或外部分类器反馈数据。

恢复、归档与纠错另带持久化操作收据。已确认但响应丢失的旧操作再次发送时，服务器返回当前密文，不重新执行旧动作；客户端处理 `operation_replayed` 时采用解密后的当前状态。

已有密文时，客户端先尝试解密第一条记录，验证共享口令后才完成登录或启用上传。错误口令不会触发迁移清理或新消息上传。空库无法凭已有消息验证口令，各设备仍须由用户确保输入完全相同的口令。Android 注册会轮换设备令牌，注册后才发现口令错误时可能需要生成新配对码重新配对；本机消息保留。

启用前请让 Android 完成短信接收并保持本机数据完整，连接稳定并等待同步结束。不要在迁移期间清除应用数据或卸载应用。启用后若本地数据库或口令丢失，服务器无法恢复消息正文；应妥善保管口令并保护设备备份。

历史备份仍可能包含旧明文数据；E2EE 启用不会改写离线备份。按备份保留策略清理旧备份。

## 静态加密与传输保护

- Android 主数据库要求 SQLCipher，数据库密钥存于安全存储；原生短信暂存队列使用 AES-GCM 与 Android Keystore。
- Go 服务将完整快照以 AES-256-GCM 加密。默认 `.key` 与数据文件并存；生产部署可用 `PRIVRELAY_STORAGE_KEY` 注入外部密钥管理器提供的 32 字节 Base64 密钥。密文和对应密钥必须一起备份。
- 正式 Android 只接受 HTTPS，系统默认验证服务端证书；WebSocket 使用 WSS。服务端支持 `-tls-cert` / `-tls-key` 直接终止 TLS 1.2+，也支持 Caddy 反向代理，HTTPS 响应设置 HSTS。
