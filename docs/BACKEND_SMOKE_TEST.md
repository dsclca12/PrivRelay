本轮使用真实后端进程、独立加密数据文件，以及本地真实 INT8 ONNX 分类器。所有短信均为合成数据，没有写入 8787 主服务的消息库。前端尚未交付，ADB 未发现设备，因此未评价浏览器页面或安卓实机体验。

## 结果

- `go test ./... -count=1 -timeout=30s`：14 项通过。
- `flutter test`：全部 13 项通过，包括消息解析、离线数据、spool、收件箱搜索、恢复、纠错、权限拒绝和大字体 Widget 测试。
- `node tools/smoke_backend.mjs`：12 项真实进程检查通过，涵盖健康检查、未授权访问、签名配对、浏览器 Cookie、网页生成安卓配对码、真实分类、重复上传、查询分页、恢复后的增量同步、纠错去重、跨域写入拒绝、服务重启保留数据、撤销设备及历史保留。

真实模型输出：

| 合成短信 | 分类 | 处理 |

| 商店优惠活动 | marketing | 在用户明确设置黑名单后进入隔离箱 |

本次三条短信批量上传并完成分类约 120 ms；这是本机、模型已加载后的单次样本，不代表 P95、冷启动、网络或压力测试指标。

## 实际可用性判断

后端核心链路可用于下一步前端和安卓联调：配对、上传、过滤、恢复、纠错与撤销均有实际请求验证。恢复后安卓增量接口能读到变更，重启后会话、消息和规则仍可用。暂未发现这轮简单流程中的功能阻断。

完整系统的实际体验仍取决于前端完成、安卓连接、HTTPS 部署和真实来信测试。当前 8787 主服务运行正常，但未配置分类器，健康检查返回 `classifier: unavailable`；独立测试用的本地分类器监听 127.0.0.1:18788。接入分类器需要在启动后端时增加 `-classifier http://127.0.0.1:18788`，或设置 `CLASSIFIER_URL`。本轮自动审批拒绝了重启主服务的操作，仅返回“策略阻止”，故主服务保持原状。

## 复跑

先构建 `artifacts/privrelay-server.exe`，并按既有 Windows 推理入口启动真实分类器，然后在仓库根目录运行：

```powershell
node tools/smoke_backend.mjs
```

脚本默认连接 127.0.0.1:18788，也可通过 `CLASSIFIER_URL` 指定。它自动创建隔离服务和密文库，结束后停止测试后端，在被忽略的 `artifacts/backend-smoke-*/report.json` 保存不含配对码或令牌的结果。本次成功报告位于 `artifacts/backend-smoke-QQfjgt/report.json`。
