# 并行审计与修复

[项目首页](../README.md) · [文档索引](README.md)

日期：2026-10-22。基于本地 `bedc7ff` 工作区，三个子智能体分别检查 Go 后端、Web 和 Android，主代理检查分类策略并汇总。子智能体因用量限制中断，已写入的改动由主代理继续检查和验证。所有测试使用合成短信和隔离存储。

## 缺陷与修复

| 优先级 | 触发及原行为 | 修复与回归 |
|---|---|---|
| P1 | 同一短信以另一 transport ID 重发，服务 ACK 新 ID 但不保存映射；该 ID 无法查询或恢复，后续更换正文还能再次入库 | 加密快照持久化 `message_aliases`；同步冲突检查、详情、恢复和纠错统一解析；验证重启、恢复、ID 冲突和落盘失败回滚 |
| P1 | 轻量模型把短信判为验证码／交易并要求复核，LLM 改判营销，原重要类别保护被绕过 | 最终策略同时检查轻量原始类别；即使黑名单或 LLM 满足隔离条件仍正常保留；覆盖两种重要类别及过滤／拦截模式 |
| P2 | LLM JSON 可附带 `primary_classification`、`confidence_calibrated`，混入可信审计元数据 | 只解析约定的类别、分数、复核与原因字段，来源及校准状态由服务端生成；增加伪造来源回归 |
| P1 | Android 处理上传响应时逐条确认／通知，后续解析或通知异常把整个批次重新标记失败，可能按旧的正常消息状态通知已隔离记录 | 完整解析后在一个本地事务内确认批次，通知在事务成功后执行；覆盖通知失败时所有 ACK 保留及隔离静默 |
| P2 | Web 当前页查询超过 5 秒时，每轮后台刷新不断使它失效，15 秒超时前的有效响应也无法展示 | 消息和审核查询进行中跳过后台刷新失效，筛选／页码变化仍作废旧结果；增加慢响应跨刷新回归 |
| P2 | Web 恢复／纠错每次点击生成新的 operation ID，服务已保存但响应丢失时重试造成重复反馈 | 同页面内同一操作共用未完成请求，失败重试保留 operation ID，成功后的新操作生成新 ID；覆盖并发点击、丢响应和页面销毁 |

## 文档承诺核对

| 当前承诺或设计目标 | 本轮处理与边界 |
|---|---|
| Android 详情显示分类来源及轻量原始结果 | 原模型解析丢弃相关字段；补齐模型解析、加密记录读写、详情来源／待复核／原始结果展示和数据库往返回归 |
| 重要短信优先保护，原始预测和最终策略分开 | 补齐 LLM 复核冲突时的保护及元数据可信边界；同步更新 AI 说明 |
| 幂等同步、ACK、恢复及纠错 | 补齐不同 transport ID 的跨重启解析和 Web 丢响应重试行为；同步更新 API 和 Web 说明 |
| Web 5 秒轮询补偿、慢请求可展示 | 修复当前页刷新饥饿；请求超时仍为 15 秒，不承诺任意网络延迟下立即成功 |
| 持续 CI 与容器加密卷重建 | 已查询真实 Actions，移除完成情况中「尚待首次验证」的过期说法；远端记录不能验证本次本地代码 |
| Android 真实来信、Doze／双卡／重启和 OEM 矩阵 | 需要真实设备和运营商来信；本轮自动测试不能代替这些验收 |
| 真实模型召回、误隔离率和延迟指标 | 需要授权的独立评估数据及真实服务，未通过放松未校准／复核保护来宣称完成 |
| PostgreSQL、迁移、多租户／角色、多实例、端到端加密 | 设计文档已明确为未来架构扩展，本轮未实现；当前交付继续标记为单用户 MVP |
| 应用锁、历史归档、英文翻译、可选前台服务、反馈训练导出 | 完成情况已明确为后续产品目标，本轮未实现，不属于已验收能力 |
