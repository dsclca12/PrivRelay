# AI / LLM 分类与自动隔离

[项目首页](../README.md) · [文档索引](README.md)

PrivRelay 保留原版 PrivateSMS-Classifier，并支持由用户配置的 OpenAI 兼容 Chat Completions API。**新安装时基础地址、模型和 API Key 均为空，LLM 默认关闭，不会自动连接 OpenAI 或其他提供商。**

本文的服务端分类／隔离适用于旧明文消息协议。当前 Android／Web 配对使用 E2EE，服务器无法读取新短信，以下配置不会对这些密文生效；当前客户端也没有端侧模型。E2EE 详情可以显示迁移时保留的分类和来源，但不代表新消息已经分类。相关功能取舍见[端到端加密](END_TO_END_ENCRYPTION.md)。

## 配置与使用

在 Web「规则配置」的「AI / LLM 自动分类」或 Android「设置 → AI / LLM 自动分类」中填写：

| 配置 | 行为 |
|---|---|
| 关闭 LLM | 继续使用原版轻量分类器；不发送 LLM 请求 |
| 失败或需复核时使用 LLM | 轻量模型失败、分类不确定或要求复核时调用 LLM；其余沿用轻量模型 |
| 直接使用 LLM | 所有新消息直接调用所配 LLM；无需运行轻量分类器 |
| API 基础地址 | 填写服务商给出的地址，通常以 `/v1` 结尾；程序追加 `/chat/completions`，不要填完整补全接口路径 |
| 模型名称 | 填写该服务实际提供的名称；没有内置默认模型 |
| API Key | 使用 Bearer 鉴权；免鉴权的本机服务可以留空 |
| 允许 HTTP | 默认关闭；只有主动开启才接受 HTTP，应仅用于可信内网 |
| 允许 LLM 自动隔离 | 默认关闭；与全局过滤模式和分数阈值共同生效 |
| 阈值 | 默认 0.95，允许 0.80～1.00；LLM 置信度与风险分数均需达到 |

启用前界面确认短信处理目的地。**发件人和完整正文将被发送到该地址**；云端服务会看到这些信息，应自行检查服务的数据保留政策。本地数据库加密不等于端到端加密。

保存后可点「测试已保存配置（合成短信）」。测试只发送固定合成文本，不读取私人消息，也不向短信库插入记录；成功表示接口能返回有效分类，不代表模型准确率或实际短信验收通过。仅改变表单但未保存时，测试仍使用服务器上已保存的配置。

配置无需重启，对新消息和待分类消息生效；不会自动重新处理全部已分类历史。

## 分类与拦截策略

分类支持 `personal`、`otp`、`service`、`transaction`、`marketing`、`suspicious`、`uncertain`。短信详情显示分类来源、模型名、分数、人工复核标记和最终策略。在 LLM 接管轻量模型复核时，额外保留轻量模型原始分类结果。

只有同时满足以下条件，LLM 才能触发可恢复的应用内隔离：

1. 全局模式为「智能过滤」或「自动拦截」。
2. 已明确开启「允许 LLM 自动隔离」。
3. 类别是营销或可疑，且不要求人工复核。
4. 置信度与风险分数均达到 LLM 阈值。
5. 未命中验证码、交易、安全内容、白名单或人工恢复保护。

LLM 自报分数**未经校准，不是实际正确率承诺**。轻量预览模型原有的未校准／人工复核保护继续保留；不会通过修改上游权重、元数据或保护条件来启用拦截。人工黑名单仍遵守重要消息保护。

轻量模型已识别为验证码或交易时，即使 LLM 复核改判为营销／可疑，最终策略仍正常保留，人工黑名单也不能覆盖该保护。分类来源、轻量原始结果和校准状态由服务端记录，LLM 响应中的同名扩展字段不能伪造这些信息。Android 详情会显示分类来源、等待复核状态及已有的轻量模型原始结果。

隔离始终可查看、恢复，不永久删除短信。PrivRelay 未持有默认短信角色时，不能抑制系统短信应用通知；本应用隔离通知保持静默。

## 失败与补偿

LLM 单次调用最多 6 秒，并受上传／补分类任务的 8 秒总预算限制；未处理完的消息保持待分类。格式错误、未知分类、非法分数、拒绝、截断、HTTP 错误或超时均正常保留，不因为模型故障拒绝短信保存。

轻量模型结果有效而 LLM 复核失败时保留轻量结果，标记等待 LLM 复核；服务器约每分钟补偿，恢复后通过消息游标和推送通知客户端。LLM 直接分类失败时保留为待分类。人工恢复结果不因重试被重新隔离。

## 接口与密钥

- `GET /api/v1/ai/settings`：查询当前配置和 `has_api_key`，不返回密钥。
- `PUT /api/v1/ai/settings`：保存配置；字段为 `mode`、`base_url`、`model`、`api_key`、`allow_http`、`auto_quarantine`、`threshold`，另支持 `clear_api_key`。
- `POST /api/v1/ai/test`：使用已保存配置执行固定合成样本测试。

三个接口均要求已授权设备或浏览器会话。密钥仅保存在现有加密快照内；表单保存成功后清空输入。相同目的地留空保留旧密钥，勾选清除会删除；修改目的地时不会自动把旧密钥带过去。服务拒绝跟随重定向，避免把凭据转发给另一个地址。

请求采用 `model`、`stream: false`、`messages`，不强制非标准参数或 JSON Schema 扩展。模型必须返回完整的 JSON 分类对象，响应使用 `choices[0].message.content` 与 `finish_reason: stop`；可接受单个 json Markdown 代码块。请求将短信作为不可信数据，程序只接受类别与分数，最终隔离动作由本地策略计算。协议依据 [OpenAI Docs 的 Chat Completions 说明](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。

## 验证边界

本轮 Go 测试覆盖配置鉴权、空白默认值、密钥加密与脱敏、目的地切换、清除、落盘回滚、分类契约、保护规则、失败保留、复核重试和恢复。真实进程冒烟使用本机模拟兼容 API，验证前端实际 API → Go → HTTP 模型响应 → 隔离 → 恢复；不连接收费服务。

未配置真实模型，因此尚未验证任何具体提供商兼容性、营销召回、误隔离率或推理延迟。测试成功不等于所有标为 OpenAI 兼容的服务均可使用；输出不符合协议时会正常保留。
