## 2026-10-22 可靠性与产品补齐

- 后端模型请求移出全局锁，在途撤销、配置变化和并发恢复不会被旧结果覆盖；后台重试轮转，WebSocket 独立写入，SIGTERM 等待在途 HTTP 和后台分类结束。
- 增加 OS 级单实例文件锁，防止两个服务或离线维护工具同时打开同一个库；增加校验清单、加密备份、恢复及输出到新目录的换钥命令。
- Web / Android 支持消息归档和取消归档，沿用消息修订同步；隔离箱不会因归档隐藏消息。Android 队列保留未同步的归档意图。
- Android 增加设备密码应用锁，后台收信同步继续运行；启用时强制开启防截屏。
- Web 支持授权导出已审核纠错样本，默认不包含正文；用途、正文授权、设备、时间与数量写入加密审计记录，不自动训练。
- 本机 Flutter 从 3.47.2 升至当前稳定版 3.47.7 / Dart 3.13.5；项目显式声明最低 Flutter 版本，Node 22 写入 `.nvmrc`。
- 增加跨平台验证和 APK / AAB 发布脚本、Caddy HTTPS 配置、CI Debug APK 产物，以及容器内上游 POSIX 测试。

本轮证据及边界见 [2026-10-22 验证记录](HARDENING_TEST_REPORT.md)。

## 追加完成功能

| 缺口 | 当前行为 |
|---|---|
| 只有轻量分类器，缺乏可配置 LLM | Web 与 Android 可设置 OpenAI 兼容 Chat Completions 基础地址、模型、密钥、关闭／主模型／失败复核模式；所有服务配置默认为空且关闭 |
| LLM 密钥保存／结果解析／调用失败没有完整闭环 | 密钥保存在 AES-GCM 加密快照，配置读取只返回 has_api_key；地址变更不沿用旧密钥、可明确清除；严格验证分类 JSON、上下文和响应长度，模型失败时不丢短信 |
| LLM 分数直接触发可能误隔离 | 自动隔离默认关闭，需单独授权；营销／可疑、无需复核且置信度／风险均过阈值；验证码、交易、安全内容、白名单、用户恢复保护优先，保留分类来源与轻量模型原始结果 |
| AI 配置无法试连或实际集成验收 | 添加只发送固定合成样本的测试入口及真实 Go 进程与本机 HTTP 假模型链路冒烟，不触达外部模型 API |
| Android 缺隐私与本地保留设置 | 增加列表正文隐藏、默认防截屏、分类消息提醒类型和可选 30／90／365 天自动清理；清理保留隔离、待上传和待处理操作相关消息，默认不自动清理 |
| 缺少持续 CI 与发布产物入口 | 新增 Go／Web／Flutter／Docker Actions 工作流、专属合成容器验收，以及 APK／AAB／混淆符号／散列清单构建脚本 |

完整的 LLM 接口与边界见 [AI 分类说明](AI_CLASSIFICATION.md)。本地合成测试不能证明某个真实服务的模型准确率；Docker 未安装的环境不能宣称容器验收已完成。

## 先前完成功能

| 原缺口 | 当前行为 |
|---|---|
| Web 搜索只覆盖已加载历史，启动最多下载 2 万条正文 | 消息页直接查询服务端全量历史，按当前页加载，每页 20 / 50 条；后台只读聚合信息，当前页随推送或 5 秒轮询刷新 |
| 拦截箱没有分页，大量记录一次渲染 | 独立服务端筛选分页，恢复末页最后一条时回到有效页；筛选变化回到第一页 |
| 统计取自浏览器缓存，已恢复数量可能不全 | 后端提供全库恢复数与当前隔离原因分布；待审核数排除已通过／已驳回记录 |
| 纠错只能提交，无法审核 | 新增纠错审核页与受鉴权保护的查询／审核接口，支持筛选、分页、查看短信、通过／驳回、审核设备和时间、已通过类别分布 |
| 反馈重试会覆盖已有状态 | 相同 operation_id 重试返回已有审核状态；已审核结论不能被相反结论覆盖；落盘失败回滚 |
| 窄窗口按钮和抽屉溢出，图标缺少名称 | 调整顶部布局、限制抽屉宽度、补齐导航和按钮名称；窄窗口纠错使用卡片，保留所有审核操作 |
| Web 请求可能长期挂起 | 请求增加 15 秒超时；搜索失败可重试，旧请求与离开页面后的响应不能覆盖新状态 |
| 操作说明存在过期内容 | 同步更新部署、Web、API 说明和文档导航 |

反馈保存在现有加密快照中。通过审核只记录结论，不修改消息分类、隔离状态、模型权重，不自动向分类器或外部服务发送样本。纠错分布按记录计数，不能当作真实模型误判率。

## 仍需完成

按投入实际使用的优先级排列：

1. **Android 真实运行验收**：多系统版本、真实双卡来信、断网 30 分钟、Doze、低电量、设备重启、后台进程回收，记录消息守恒和最终补发证据；本轮单元测试不能替代这些验证。
2. **真实模型与策略验收**：使用有代表性且经授权的独立数据，测量营销召回、正常／验证码／交易误隔离、不确定比例与端到端 P95。当前模型的校准／复核保护继续保留。
3. **生产部署与发布**：先前 Docker Compose、卷内备份恢复／换钥和本地 TLS 代理的实测范围见[可靠性报告](HARDENING_TEST_REPORT.md)；公网证书签发、长期运行、真实断电／磁盘故障及生产压力仍需验收。本次合并后的 CI 与本地结果见[并行审计](AUDIT_2026-10-22.md)，正式签名需要运营者私钥。
4. **可选产品功能**：英文 ARB 翻译、可选前台实时服务。历史归档与应用锁已实现，应用锁原生密码确认仍需真机验收。默认短信应用与历史导入／发送属于单独的平台扩展，不能只增加权限就宣布完成。
5. **架构扩展**：PostgreSQL、迁移、多租户、权限角色和多实例尚未实现；现有服务仍是单用户、单进程快照存储。端到端加密已实现独立密文协议，仍需独立安全审计、口令恢复和实机迁移验收；它不能与服务端读取正文的分类功能同时使用。
6. **反馈后续用途**：授权样本导出与用途审计已具备；上游训练数据导入、数据集治理、完整授权撤回及自动训练仍未实现。服务端自动保留期限／跨设备删除尚未实现，现有自动清理仍仅作用于 Android 本地。

项目当前仍应标记为可联调的 MVP，而非已经完成生产稳定性与全部立项验收。
